<objective>
Repair the two requirement statements this phase cannot pass as written, and correct the one
factual error in the project's technology contract that produced one of them.

`01-RESEARCH.md` Pitfall 1 verified, from `rand` 0.10.2 crate source and by compiling, that the
small-RNG type is unconditional in `rand` 0.10 — only the standard-RNG type is feature-gated.
CORE-03 as written demands that both be absent from the dependency graph, which is unachievable
without forking the crate, so the Phase 1 gate would read as failed forever. CORE-10 as written
forbids any hardcoded parameter, which on a literal reading pulls a numerical-method iteration
count into an economics config where someone would eventually tune it — and tuning it silently
changes every trajectory.

Purpose: both amendments are the user's own contract being edited, so each ships with its
rationale in the same diff. That is the difference between an auditable restatement and a quiet
loosening. Per D-17 and D-18 the user delegated these explicitly.

Output: an amended `.planning/REQUIREMENTS.md` and a corrected `.claude/CLAUDE.md`, committed
together so the reason survives alongside the change.
</objective>
