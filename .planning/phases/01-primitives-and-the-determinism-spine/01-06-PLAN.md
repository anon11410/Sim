<objective>
Make the config file the whole input. Every simulation and economic parameter becomes a typed key
with no default anywhere behind it, an unknown key is a hard error, and the hash that identifies a
run is taken over the file's raw bytes.

Purpose: CORE-10 exists because a serde default is a hidden hardcoded parameter — a value that
changes the trajectory while appearing nowhere in the committed input. `01-RESEARCH.md` Pitfall 7
verified that the grep the ROADMAP's criterion names is necessary but not sufficient: an optional
field type defaults silently with no attribute to grep for. The only check that actually proves the
requirement is an exhaustive loop that deletes every key in turn and asserts each deletion is
rejected by name.

Output: `src/config.rs` carrying the full schema, `config/baseline.toml` carrying every parameter,
and `tests/config_strict.rs` carrying the exhaustive proof.
</objective>

    Write these named tests:

    1. `every_key_is_required` — the test that actually enforces CORE-10. Read
       `config/baseline.toml` as text, parse it into a generic TOML value, enumerate every LEAF key
       with its table path via a small recursive helper, and for each: clone the document, remove
       that key, re-serialise, and assert the parse into `Params` fails with an error whose text
       contains `missing field` followed by that key's name. Include the table path in the failure
       message so a regression names the offending key. This loop is what proves no hidden default
       survives anywhere in the schema; the source greps are a cheap complement, not a substitute.
    2. `unknown_key_inside_a_table_is_rejected` — append a misspelled key inside an existing table;
       the error text contains `unknown field`.
    3. `unknown_table_is_rejected` — append a table the schema does not declare; the error text
       contains `unknown field`.
    4. `empty_config_is_rejected` — an empty string fails with `missing field`, so an empty file
       cannot produce a fully-defaulted parameter set.
    5. `removed_value_is_rejected` — a key left with no value on its right-hand side fails with
       `TOML parse error`, before the deserializer runs.
    6. `float_where_int_is_not_coerced` and `string_where_int_is_not_coerced` — each fails with
       `invalid type`. This is the property CLAUDE.md rejects a layered configuration crate for.
    7. `key_order_does_not_change_params_but_does_change_the_hash` — build a reordered copy of the
       shipped file by emitting its tables in reverse order, assert the two parses produce equal
       `Params` values, and assert the two byte hashes differ. Hashing the bytes rather than the
       parsed struct is deliberate: a comment change is a hash change, which is correct, because
       the comments plan `01-08` adds carry the source grades CORE-11 makes load-bearing.
    8. `hash_is_stable_across_repeated_computation` — the same bytes hashed twice give the same

| Boundary | Description |
