<objective>
The tracer for this phase: wire one capability through every layer this phase will
touch, end to end, and prove it with a real runnable check before any expansion
work begins.

The capability is: **a library tick loop that moves money through the books each
tick halts at exactly the tick that records no transaction, when the liveness gate
is on — and runs to completion when it is off.** That single path crosses the
config layer (the gate), the ledger (construction, endowment, transfer, journal),
the invariant layer (an ordered check set returning `Result`) and the caller's loop
(`?` propagation and abort). It is the one violation reachable through the entirely
public API, which is why it can be driven from an integration test with no fault
injection at all.

Purpose: if this architecture is wrong, it is wrong after one commit rather than
after five. Every later plan in this phase widens this slice — goods (02-03),
non-negativity and zero-sum (02-04), the seeded corruptions (02-05), the property
tests (02-07) and the LEDG-02 lint wall (02-06) — and none of them changes its
shape.
Output: two new library modules, their registration, and one integration test.

**One slice, two commits — read this before starting.** Tasks 1 and 2 are the two
halves of a single tracer slice, split at the module seam and at nothing finer.
This plan is the largest in the phase (projected 92k against a 100k smart-zone
budget, on a `confidence: low` figure with no completed phase to calibrate
against), and an undershoot inside an unsplittable task would exhaust the window
with no commit boundary to resume from. The seam gives that boundary at zero
architectural cost.

Two rules follow, and they are what stop the split becoming a horizontal-layer
decomposition:

1. **Task 1 is not shippable value and must not be treated as such.** `src/books.rs`
   on its own is a layer, not a slice. Do not add call sites, convenience methods,
   goods operations or anything else "while you are in there" — every addition
   beyond what task 2 consumes widens a layer before the architecture is proven.
2. **Task 2 must run in the same phase of work, and no expansion plan may begin
   until its end-to-end check passes.** If task 1 lands and the run is interrupted,
   resume at task 2 — `src/books.rs` and its registration are committed, so the
   resumed run reads them from disk and does not rebuild them. The slice is not
   proven until `cargo test --locked --release --test invariant_halt` is green.

|----------|-------------|
| caller -> `Books` | Every later economic phase crosses this boundary. Untrusted only in the sense that a caller bug must not be able to conjure or destroy money. |
