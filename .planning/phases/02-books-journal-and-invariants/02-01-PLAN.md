<objective>
Lay the two contracts the rest of the phase is written against, and close the one
cross-phase gap the research surfaced.

The liveness check needs a config gate (LEDG-08) and the gate is a four-file change
policed by three existing tests. The halt messages need every ledger address to
render as a string (LEDG-09) and no address type has a `Display` impl today.

And the two authoritative sources need amending, in three separate ways. Both the
ROADMAP criterion and LEDG-09 still describe localisation as a search this phase
proves unsound and whose spelling three of its own plans make a hard grep failure —
so as written, Phase 2 would close against a criterion describing an algorithm it
forbids. ROADMAP Phase 2 criterion 2 also says "halts the run", which Phase 2
cannot demonstrate at the process level because it has no run loop; and criterion 1
requires `Household` and `Firm` to carry no balance fields, which Phase 2 cannot
demonstrate because those types do not exist yet. Both halves have to be written
down against Phase 3 or they fall between the phases (LEDG-01, LEDG-10). Finally,
criterion 3 requires the gate to be on "by default from Phase 6" and Phase 6's
entry says nothing about it, so nothing schedules the shipped value to flip.

Purpose: plan 02-02's tracer cannot compile without the config field, and cannot
render a `Violation` without these `Display` impls; and the phase gate reads the
ROADMAP criterion literally, so the criterion has to describe what gets built.
Output: one new config table, five `Display` impls, one amended criterion, one
amended requirement with its rationale block, and three new cross-phase criteria.
</objective>
