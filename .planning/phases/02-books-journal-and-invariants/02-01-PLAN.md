cross-phase gap the research surfaced.

render a `Violation` without these `Display` impls.

</objective>

    Implement `std::fmt::Display` for `HouseholdId`, `FirmSlot`, `GoodId`, `FirmId` and
    `Account` so that the halt messages authored in plan 02-02 can interpolate an
    address directly. Every `Violation` variant in this phase names an agent, and the
    error-message crate renders a nested field through its `Display` impl, so without
    these the messages either do not compile or degrade to a debug dump.

    Render exactly these forms, and pin each one in a unit test:
    `HouseholdId(12)` as `household:12`; `FirmSlot(3)` as `firm-slot:3`;
    `GoodId(0)` as `good:0`; `FirmId { slot: FirmSlot(3), generation: 0 }` as
    `firm:3:0`; `Account::Household(h)` as the household form and `Account::Firm(f)`
    as the firm form, delegating to the inner impls rather than re-spelling them.

    Two properties make these load-bearing rather than cosmetic, and both belong in the
    doc comment. First, the firm form carries the generation, because a halt naming
    slot 3 without saying which occupant is ambiguous across a Phase 10 respawn — this
    is the same reasoning that put the generation in the identity in the first place.
    Second, the rendered form contains no path, no host name, no wall-clock reading and
    no process id: a halt message reaches stderr and is read next to a diffed log, and
    TICK-06 forbids all four from anything a run emits.

    Add a `#[cfg(test)] mod` (or extend the existing `mod tests`) with one test asserting
    all five rendered strings by equality, and one test asserting that the firm form of
    two identities sharing a slot but differing in generation renders differently. Use
    plain `assert_eq!` on the full string; a `contains` assertion would pass on a debug
    dump.

    Do not derive or hand-write `Display` for anything else in this file, and change no
    existing type, derive or method.
  </action>
