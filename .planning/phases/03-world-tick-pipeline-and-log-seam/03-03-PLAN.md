    Add the decision-provenance table to the log module.

    `ProvenanceRow` is flat and has seven columns: the tick, the agent as a rendered address, the
    decision type, two integer inputs, an integer outcome, and the **rule** — which branch of the
    decision actually fired. The decision type and the rule are fixed enumerations of static
    strings, not free text; that is what makes TICK-07's "never free text" true by construction
    rather than by review. The rule column is the highest-value field and costs nothing: when
    prices spiral in Phase 9, a frequency count over it localises the bug to a branch in one
    query.

    No column may be optional. An absent value in a CSV writes an empty cell, and the Python
    reader then infers a floating column for what is otherwise an integer one — exactly the
    degradation the integer-cents decision exists to prevent. If a value can genuinely be absent
    later, use a documented sentinel integer.

    Extend the sink trait with a provenance method, implement it on all three sinks, and have the
    disk writer open `provenance.csv` **with its header written eagerly at construction**, before
    any row exists.

    Two measured facts make the spelling non-obvious and both must be honoured. First, the CSV
    writer emits its own header on the first serialised row, so writing a header as well produces
    **two** identical header lines, and the Python reader then treats the second as a data row of
    strings and widens every column. Build the writer with automatic headers turned off and write
    the header record explicitly. Second, without an eager header a run with no rows leaves a
    **zero-byte** file, and the Python reader raises on that rather than returning an empty
    frame. This phase writes zero provenance rows by definition, so this is not hypothetical — it
    is the default outcome.

    Derive the header from the serde implementation using the same mechanism plan 03-02
    introduced for the tick file, so there is exactly one source of column names in the module
    and a renamed field cannot leave a stale hand-typed header behind.

    **One consequence to hand forward to Phase 4, and to record in the SUMMARY:** a header-only
    CSV gives every column the object dtype, not an integer one. Phase 4's dtype assertion must
    therefore be conditional on a non-empty frame, or must read the dtype from the generated
    schema — which is one of the reasons the schema carries dtypes at all.

    Add unit tests in the module for the behaviours listed above, including explicitly the
    single-header case, since the double-header defect is silent and produces a file that still
    opens.

    **First, the wire-format label.** Add a public string constant to the log module naming the
    schema version, and record it in the provenance document. Two constraints on it, and the
    first is measured.

    Spell the version **without a decimal literal**. The float-confinement guard reads whole
    lines and is deliberately blind to both comments and string literals — Phase 1 recorded that
    *"a heuristic that skips comments is one someone later widens to skip a string"* and reworded

    emitted JSON, build it from integer constants and concatenate.

    copying the shape of the three that are already there. The justification is the one CORE-10's
    carve-out asks for: a schema version is neither an economic parameter nor a numerical-method
    constant — it is a wire-format label, and routing it to configuration would make it tunable as
    though it described the economy, besides dragging in the five-part config-leaf agreement for a
    string nothing in the model reads. State plainly, as the existing rows do, that being code
    rather than configuration does not make it free to change: bumping it invalidates the
    committed schema and the committed golden run, which is exactly the point of making the change
    a deliberate source-level act. Section 4's rows have no counterpart in section 2 and the
    provenance tests do not expect one, so this addition disturbs neither of them — but run those
    tests rather than trusting this sentence.

    **Then the run record itself.** Add a build script at the package root that captures the
    compiler's version string at build and exposes it to the binary as a compile-time environment value, and re-runs when the
    script itself changes. Capturing it at build time rather than by invoking the compiler during
    a run keeps a process spawn off the behaviour path entirely.

    Then have the binary write `run_meta.json` into the run directory, carrying: the schema
    version, the effective seed, the configuration hash, the compiler version string, the number
    of ticks completed, and the run's outcome as a short fixed word. Write it on **both** paths —
    a clean finish and a halt — so that a halted run is self-describing: the research measured a
    liveness halt producing a complete record with zero ticks completed and a violation outcome.

    This file is the single quarantined non-deterministic surface. It is excluded from the
    determinism diff, and it is the only file in the run directory that may carry a wall clock.
    If a start time is wanted, it goes here and nowhere else.

    **Do not record a duration.** A run's own record would then differ between two otherwise
    identical runs, which invites someone to "fix" a failing determinism test by widening it —
    and the widening would be permanent while the reason for it would be forgotten. The two
    outcome fields carry everything a reader needs about how the run ended.

    Keep every value in the record either an integer, a fixed word, or a hex digest. No path, no
    host name, no process identifier: the exclusion from the diff is about the wall clock, not a
    licence to put the environment in a file that ships beside the logs.

    Note that adding a build script does not change anything the toolchain guard checks — it
    searches the git index for build-configuration files by name and searches the normal-edge
    dependency graph — but run the guard rather than reasoning about it.
